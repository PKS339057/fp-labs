## Задача 6. Квадрат суммы минус сумма квадратов

**Условие.** Найти разность между квадратом суммы и суммой квадратов натуральных чисел
от 1 до 100. Ответ: 25164150.

**Идея.** Посчитать сумму 1…n и сумму квадратов 1…n, затем вычесть. Варианты различаются
тем, как получаются эти суммы. Тип `Integer` — чтобы не было переполнения при больших n.

**Область определения.** n — любое целое; при n ≤ 0 все варианты дают 0.

### Хвостовая рекурсия

```haskell
sumSquareTail :: Integer -> Integer
sumSquareTail n = go 1 0 0
 where
  go i total squares
    | i > n = total * total - squares
    | otherwise = go (i + 1) (total + i) (squares + i * i)
```

Вызов `go` — последнее действие ветки, промежуточные суммы передаются аккумуляторами.

### Обычная рекурсия

```haskell
sumSquareRecursive :: Integer -> Integer
sumSquareRecursive n = total * total - sumSquares n
 where
  total = sumTo n
  sumTo k
    | k <= 0 = 0
    | otherwise = k + sumTo (k - 1)
  sumSquares k
    | k <= 0 = 0
    | otherwise = k * k + sumSquares (k - 1)
```

После возврата из `sumTo (k - 1)` ещё нужно сложение, поэтому вызов не хвостовой
и глубина стека растёт с n.

### Генерация → фильтрация → свёртка

```haskell
sumSquareModular :: Integer -> Integer
sumSquareModular n = foldl' (+) 0 products
 where
  numbers = [1 .. n]
  pairs = [(i, j) | i <- numbers, j <- numbers]
  products = map (uncurry (*)) (filter (uncurry (/=)) pairs)
```

Квадрат суммы — это сумма произведений i·j по всем парам. Пары с i = j дают сумму
квадратов, поэтому фильтр оставляет пары с i ≠ j. Сложность O(n²), у остальных
вариантов — O(n).

### Отображение map

```haskell
sumSquareMap :: Integer -> Integer
sumSquareMap n = total * total - sum squares
 where
  numbers = [1 .. n]
  squares = map (\x -> x * x) numbers
  total = sum numbers
```

### Списковое включение

```haskell
sumSquareComprehension :: Integer -> Integer
sumSquareComprehension n = total * total - sum [x * x | x <- [1 .. n]]
 where
  total = sum [1 .. n]
```

### Бесконечный список

```haskell
sumSquareInfinite :: Integer -> Integer
sumSquareInfinite n = total * total - sum (map (\x -> x * x) numbers)
 where
  numbers = takeWhile (<= n) [1 ..]
  total = sum numbers
```

`[1 ..]` ленивый: элементы создаются, только когда их запрашивает `takeWhile`,
и он останавливается на первом числе больше n.

## Задача 15. Маршруты по сетке

**Условие.** Сколько маршрутов ведёт из левого верхнего угла сетки 20×20 клеток в правый
нижний, если ходить только вправо и вниз? Ответ: 137846528820.

**Идея.** Любой маршрут — это 2n шагов, из них ровно n вправо. Маршрут однозначно задаётся
тем, какие n шагов из 2n будут «вправо», поэтому ответ C(2n, n) = (n+1)·…·(2n) / n!.
Тип `Integer` обязателен: уже при n = 20 произведение 21·…·40 не помещается в 64 бита.

**Область определения.** n ≥ 0; при n = 0 ответ 1 (пустой маршрут). При n < 0 вариант
с треугольником Паскаля падает на отрицательном индексе, остальные возвращают 1.

### Хвостовая рекурсия

```haskell
pathsTail :: Integer -> Integer
pathsTail n = go 1 1 1
 where
  go i top bottom
    | i > n = top `div` bottom
    | otherwise = go (i + 1) (top * (n + i)) (bottom * i)
```

Аккумуляторы копят числитель (n+1)·…·(n+i) и знаменатель 1·…·i; начинают с 1 —
нейтрального элемента умножения.

### Обычная рекурсия

```haskell
pathsRecursive :: Integer -> Integer
pathsRecursive n = productFrom (n + 1) (2 * n) `div` productFrom 1 n
 where
  productFrom a b
    | a > b = 1
    | otherwise = a * productFrom (a + 1) b
```

### Генерация → фильтрация → свёртка

```haskell
pathsModular :: Integer -> Integer
pathsModular n = multiply (filter (> n) numbers) `div` multiply (filter (<= n) numbers)
 where
  numbers = [1 .. 2 * n]
  multiply = foldl' (*) 1
```

Генерируются числа 1…2n, фильтр делит их на числитель (> n) и знаменатель (≤ n),
свёртка перемножает. `multiply` — частичное применение `foldl'`: не хватает только списка.

### Отображение map

```haskell
pathsMap :: Integer -> Integer
pathsMap n = product (map (n +) [1 .. n]) `div` product [1 .. n]
```

### Списковое включение

```haskell
pathsComprehension :: Integer -> Integer
pathsComprehension n = product [n + i | i <- [1 .. n]] `div` product [1 .. n]
```

### Бесконечный список: треугольник Паскаля

```haskell
pathsInfinite :: Integer -> Integer
pathsInfinite n = pascal !! fromInteger (2 * n) !! fromInteger n
 where
  pascal = iterate (\row -> zipWith (+) (0 : row) (row ++ [0])) [1]
```

`pascal` — бесконечный список строк треугольника: следующая строка — сумма текущей,
сдвинутой вправо и влево. Из-за ленивости вычисляются только первые 2n + 1 строк.
Элемент n строки 2n равен C(2n, n). Сложность O(n²) против O(n) у остальных вариантов.

## Реализация на Python

```python
"""Задачи Эйлера 6 и 15 обычными циклами — для сравнения с Haskell."""


def sum_square_difference(n: int) -> int:
    total = 0
    squares = 0
    for i in range(1, n + 1):
        total += i
        squares += i * i
    return total * total - squares


def lattice_paths(n: int) -> int:
    # row[x] — число маршрутов до узла x в текущей строке узлов.
    # В первой строке все единицы: вдоль края путь один.
    # В узел приходят сверху или слева: row[x] (сверху) += row[x - 1] (слева).
    row = [1] * (n + 1)
    for _ in range(n):
        for x in range(1, n + 1):
            row[x] += row[x - 1]
    return row[n]


if __name__ == "__main__":
    print(sum_square_difference(100))
    print(lattice_paths(20))
```

## Выводы

Хвостовая и обычная рекурсия отличаются тем, что остаётся сделать после вызова. В хвостовой
ничего — состояние едет в аккумуляторах, стек не растёт. В обычной после возврата ещё
сложение или умножение, поэтому стек растёт с n. Но в Haskell хвостовая рекурсия не
гарантирует экономию: из-за ленивости аккумуляторы могут копить отложенные вычисления
вместо чисел.

Модульный вариант нагляднее всего: генерация, фильтр и свёртка разделены, каждый этап
понятен отдельно. Но в задаче 6 за наглядность пришлось заплатить сложностью O(n²).
Варианты с `map` и списковым включением получились самыми короткими и читаемыми;
включение — по сути та же связка `map` и `filter`, только другой записью.

Бесконечные списки удобны, когда заранее неизвестно, сколько элементов понадобится:
список описывается целиком, а вычисляется ровно столько, сколько запросили. Ленивый
список отличается от итератора Python тем, что запоминает уже вычисленные элементы и
его можно обходить повторно; итератор одноразовый.

В Python те же задачи решаются циклом с изменяемыми переменными. В Haskell изменяемых
переменных нет, поэтому состояние приходится передавать явно — через аргументы рекурсии
или через свёртку. Это непривычно, зато каждая функция зависит только от своих аргументов,
и её легко проверить отдельно.

Отдельный вывод про типы: `Int` в задаче 15 молча переполняется уже на промежуточном
произведении, поэтому везде используется `Integer` с длинной арифметикой.
